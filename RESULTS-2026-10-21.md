# Test progression and final patch

## Device observations

One B1 HW 6.01/FW 6.19 was tested with 50 x 30 mm original gap labels, with and without their RFID tag. Unless stated otherwise, density was 3. Observations are operator reports; not all have instrumented measurements.

| Variant | Observation |
|---|---|
| Upstream density | Visible tagless printing; tagged output approximately 2x taller. |
| Stock motor ramp restored | Tagged stretch persisted. |
| RFID-only (one-byte stock change) | Tagged square measured 20 mm with calipers; 25 mm ruler span measured about 25.3 mm. Tagless job advanced two labels but was blank. |
| RFID-only, after calibration | Four blank labels advanced. First print offset about 6 mm; second and third aligned. |
| Stock-feed literals restored | Tagless scale correct; tagged stretch persisted. |
| `nofeed32` | Reduced the RFID retry feed. Operator reported roughly one misaligned label on loading, then correct alignment. Not an automatic first-label fix. |
| `tagaspaper` renderer branch experiment | Tagged stretch persisted. This experiment is not included in the final build. |
| `nofeed32_tagstock` | Restoring tagged-path coefficients corrected tagged scale; tagged output fast and high contrast. Tagless output still slower/fainter. |
| `tagstock_untaggedmode0` | Changing file 0x612c alone produced no observed improvement in tagless speed/contrast. |
| **`mode0_densitytest`** | After the final density-handler change, operator reported tagless speed and contrast matching tagged output. Final dimensions, tagged regression, first-label registration and long-run results have not been separately recorded. |

The latest success is meaningful but does not close every earlier issue. No statement of full calibration, thermal safety, third-party-media compatibility or long-term reliability is supported.

## Reproduction recipe

The build starts with the exact upstream density image, not an arbitrary installed firmware. File offsets below use an exclusive end. Firmware virtual address = file offset + `0x01010000`.

| Offset(s) | Final change relative to upstream density |
|---|---|
| `0x1d21c..0x1d29c` | Restore 128 bytes of stock motor ramp. |
| `0x1e60..0x1e70` | Restore four stock literals used by a feed-counter path. |
| `0x6614..0x6628` | Restore five tagged-renderer literals. |
| `0x6d50..0x6d60` | Restore four tagged-renderer literals. |
| `0x15442` | `41 -> 01`: retry-feed count expression changes from 0x820 to 32. |
| `0x612c` | `03 -> 00`: initial mode selection chooses zero on the alternate path. |
| `0xdb64..0xdb66` | `0b 70 -> 00 bf`: replace the density-handler fallback mode store with Thumb NOP. |

Upstream RFID bypasses, density hooks, and shared renderer coefficients remain present. The final build does not contain the experimental renderer-branch NOPs from `tagaspaper`.

### Why the final change matters

In the density handler, valid settings 1..5 initially select mode0. A later check of tag presence, usage and a media field can reach `0x0101db5e`. For non-continuous media, instruction `0x0101db64` writes mode3 to `0x000204ca`. The previous patch at `0x0101612c` did not remove this second selection path. The final NOP removes that store. The operator's comparison supports this path's relevance to the observed speed/contrast difference; there is no hardware execution trace proving the full sequence of mode writes.

A prior handoff incorrectly described `0x01015efa` as resetting the mode to three. In the inspected routine, r5 is initialized to zero and stored at `0x01015efc`: that path writes zero.

### Verification and provenance

The final file was locally reconstructed by `scripts/build_final.py` from hash-verified stock and upstream-density images and matched the operator-tested artifact byte for byte. The builder also checks patch-site bytes and final output hash. The final two-byte instruction change was decoded as NOP using Capstone. These checks do not emulate the printer or demonstrate thermal equivalence.

- Size: 124436 bytes
- SHA-256: `bdbe795844d700b07da4c249cd9bce81b1cb785349de2ec9abf528da16cfffe1`
- Parent SHA-256: `6c3c0762e21b035eeb3bdd931e353b9620d0945a712f11a3a6b4ee5ed19e635c`
- Exactly two changed bytes versus that parent, at file offsets 0xdb64 and 0xdb65.

The operator received the flash command and subsequently reported the successful comparison. No final-flash console log or flash readback was captured in this session. The result is recorded as operator-reported installation/testing, not independently read-back device identity.

## Remaining checks

- Final-image ruler dimensions with and without a tag; fresh tagged-media regression.
- First label after loading at different positions; first three labels after calibration.
- Repeated labels and cumulative alignment drift; USB and Bluetooth on the final image.
- Other densities and real third-party media under controlled conditions.
- Thermal behavior, long-term head wear, and tested stock recovery remain unknown.

Do not publish any of these as passing until the corresponding observation exists.
